## 02 · WHY

- 문제 제기부터: "카탈로그가 없는 조직에서 흔히 반복되는 질문들이 있습니다" — 슬라이드의 4개 질문 하나씩 짚어주기 (다 읽지 말고 톤만 살려서 2~3개는 강조, 나머지는 가볍게).
- 원인 설명: "조직의 데이터 규모와 종류가 늘고, 활용 환경이 복잡해지면서 데이터가 여러 시스템에 흩어집니다. 그러다 보니 어디 있는지, 무슨 의미인지, 어디서 나와서 믿을 만한지, 어떻게 쓰이는지, 누가 관리하는지 파악이 안 됩니다."
- 핵심 한 줄로 마무리: "결국 네 질문의 공통점은 하나입니다 — 데이터에 대한 정보를 한곳에서 파악하기 어렵다는 것."

## 03 · WHY OPENMETADATA (강점)

- 브릿지: "이런 문제를 해결하기 위해 사용하는 것이 데이터 카탈로그입니다. 오픈소스 데이터 카탈로그에도 OpenMetadata나 DataHub 같은 여러 프로젝트가 있는데요, 오늘은 그중 OpenMetadata가 이런 문제를 어떻게 해결하는지 살펴보겠습니다."
- 정의: "OpenMetadata는 조직에 흩어져 있는 데이터의 메타데이터를 한곳에 수집하고, 검색하고 관리할 수 있도록 해주는 오픈소스 메타데이터 플랫폼입니다."
- 강점 카드 4개(오픈소스 / 130개+ 커넥터 / UI 중심 운영 / 올인원 플랫폼)는 다 읽지 말고 톤만 살려서 훑기.
- 마무리 한 줄: "오픈소스 데이터 카탈로그 시장에서 OpenMetadata가 특히 주목받는 배경이 바로 이 4가지입니다."

- [Connector 설명 + 스케일]
공식적으로 Database, Dashboard, Pipeline, Messaging, ML Model, Storage 등 다양한 영역에 걸쳐 130개 이상의 Connector를 지원하고 있습니다.”
“각 시스템의 접속 정보를 등록하면 Connector가 해당 시스템에 접근해서 스키마, 테이블, 컬럼 같은 메타데이터를 수집하고 OpenMetadata 카탈로그에 반영합니다.”
“이 Ingestion을 주기적으로 실행하도록 스케줄링할 수도 있어서, 원본 시스템의 변경사항을 카탈로그에 지속적으로 반영할 수 있습니다.”

- 마무리: "즉 오늘 보여드리는 Postgres·Airflow 연동은 130개 중 두 가지 예시일 뿐이고, 조직의 데이터·AI 자산 전체를 하나의 카탈로그로 묶을 수 있다는 게 핵심입니다."

## 06 · 시연 (라이브 데모 — 가장 중요)

> 화면 전환하면서 말이 끊기기 쉬운 구간입니다. 각 스텝 시작 전에 "지금부터 ~하겠습니다"로 먼저 말하고 조작하세요 — 침묵하며 클릭만 하는 것보다 훨씬 자연스럽습니다.

**01 — DBeaver로 원본 확인**
"본격적인 시연에 앞서, DBeaver로 연결된 원본 Postgres를 먼저 보여드리겠습니다. customers, sales 두 테이블이 있는데, 지금은 이게 뭘 의미하는지 아무 설명 없는 '날것' 상태입니다."

**02 — 카탈로그된 데이터 기반 기능 소개**
"이제 같은 테이블을 OpenMetadata에서 검색해보겠습니다. 이미 카탈로그로 등록해둔 상태라 스키마와 설명이 자동으로 붙어있는 걸 확인할 수 있어요. 컬럼 타입·설명까지 추론되어 있고, Tier·Domain 같은 거버넌스 정보, Glossary에 연결된 비즈니스 용어까지 한 화면에서 확인할 수 있습니다."

**03 — DB 서비스 등록 & 카탈로그화 시연**
"이번엔 완전히 새로운 DB를 하나 등록해보겠습니다. manufacturingdb라는 별도 Postgres 인스턴스인데, Add New Service부터 실시간으로 진행하면서 접속 정보만 입력하면 factories, production_orders 테이블이 자동으로 카탈로그에 올라오는 걸 보여드리겠습니다."

**04 — Airflow DAG 실행 및 카탈로그화**
"다음은 Airflow입니다. customers와 sales를 조인해서 customer_sales_summary라는 새 파생 테이블을 만드는 DAG를 실행하겠습니다. DAG가 끝나면 Ingestion을 재실행해서, 방금 생긴 새 테이블이 카탈로그에 바로 반영되는 것까지 확인하겠습니다."

**05 — Lineage**
"이제 리니지입니다. customers, sales가 join되어 customer_sales_summary가 만들어졌다는 관계, 그리고 이 테이블을 만든 Airflow DAG까지 UI에서 직접 연결해서 보여드리겠습니다. 참고로 OpenMetadata는 쿼리 로그를 분석해서 이런 관계를 자동으로 감지하는 기능도 지원하는데, 오늘은 수작업으로 보여드립니다."

**06 — Connectors**
"마지막으로 커넥터 화면입니다. Add New Service 목록을 열어서 Snowflake, Kafka, S3 같은 다른 소스도 같은 방식으로 붙일 수 있다는 걸 시각적으로 보여드리겠습니다."

## 07 · WRAP-UP (기대효과 & 느낀 점)

- 기대효과 카드 3개(데이터 탐색 시간 단축 / 관리 효율성 / 데이터 신뢰도 향상)는 다 읽지 말고 톤만 살려서 훑기.
- 느낀 점은 아래 4가지를 자연스럽게 풀어서 말하기:
  1. **정보를 한곳에서 확인할 수 있어 편리함** — 테이블·컬럼 정보뿐만 아니라 비즈니스 용어, 담당자 등의 정보를 하나의 플랫폼에서 함께 확인할 수 있어 데이터 파악이 편리했음.
  2. **다양한 데이터 소스를 연결할 수 있다는 점** — DB, BI, Pipeline 등 다양한 데이터 서비스를 지원하며, 접속 정보를 기반으로 비교적 쉽게 등록하고 메타데이터를 수집할 수 있다는 점이 인상적이었음.
  3. **데이터 간 관계와 흐름을 직관적으로 파악 가능** — Lineage를 통해 데이터가 어디에서 생성되고 어떻게 연결·가공되는지 시각적으로 확인할 수 있어 데이터 흐름을 이해하는 데 유용했음.
  4. **(아쉬운 점) 지속적인 사용자 관리가 필요함** — 용어, 컬럼 설명, Tier 등 일부 정보는 자동 수집만으로 완성되지 않고 사용자가 직접 정의·관리해야 함. 결국 구성원들이 지속적으로 관심을 갖고 관리할수록 활용 가치가 높아지는 플랫폼이라고 느낌.

## Q&A 대비 메모

**"자동 리니지는 어떻게 만들어지나요?"**
→ "OpenMetadata의 Lineage ingestion pipeline이 소스 DB의 쿼리 로그(Postgres는 pg_stat_statements)를 주기적으로 읽어서, 캡처된 SQL을 파싱해 source→target 테이블 관계를 추출하고, 메타데이터와 동일한 ingestion API로 카탈로그에 반영합니다. 저희 환경에서 켜려면 ① pg_stat_statements 활성화, ② 읽기 권한 부여, ③ 이미 자동 생성된 Lineage 파이프라인 스케줄만 켜면 됩니다."

**"S3나 Ceph 같은 스토리지도 되나요?"**
→ "S3는 정식 지원되고, MinIO 같은 S3 호환 스토리지도 엔드포인트만 커스텀으로 지정하면 됩니다. 다만 DB와 달리 파일 안 스키마를 잡으려면 버킷에 매니페스트 파일이나 프로파일러 설정이 추가로 필요합니다."

**"DataHub 말고 왜 OpenMetadata인가요?"**
→ 직접 검증하지 않은 비교 주장은 피하고, 본인이 실제로 겪은 경험 위주로 답하기 (예: "UI만으로 로컬 환경 구축부터 시연까지 직접 다 돌려봤는데 진입장벽이 낮았습니다").
